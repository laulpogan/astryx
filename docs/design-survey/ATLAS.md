# Astryx 2026 Web-Design Landscape Atlas

Evidence base: 478 sites/docs indexed → 85 selected for deep-crawl → 68 completed dossiers (65 structured rows in `dossiers.jsonl` + 3 file-only: `modal-labs.md`, `onlook.md`, `web-design-trends-2026-muzli.md`). Every claim below cites a dossier slug. See §6 for full method notes.

## 1. Executive read — the 12 findings that change the plan

**Peer-set caveat (read before the ADOPT verdicts below):** Recounted from `dossiers.jsonl`'s own `relation` field (`exemplar`/`counter-trend` = sites, `trend-doc` = commentary/press, not sites) rather than treating all non-peer rows as one marketing-site bucket. Of the 65 structured dossiers: **47** (`relation: exemplar`/`counter-trend`, excluding the 8 peers below) are funded AI-startup/devtool marketing sites — not Astryx's literal peer set; **10** (`relation: trend-doc`, excluding 2 of the 8 peers below that carry that tag) are trend-docs/press commentary, not marketing sites at all — `webflow-blog-8-web-design-trends-to-watch-in-2026`, `ai-in-design-report-2026-stateofaidesign-com`, `apple-newsroom-liquid-glass-announcement-june-2025`, `wwdc25-meet-liquid-glass-session`, and `studiomeyer-io-web-design-trends-2026-reality-chec` among them (plus the file-only `web-design-trends-2026-muzli`, the same kind of commentary but outside this 65-row count); the remaining **8** are real design-system/component-library/docs-as-product sites (`heroui-v3-formerly-nextui`, `radix-ui-themes-theme-overview-docs`, `park-ui-panda-css-ark-ui-homepage`, `shadcn-ui-theming-docs`, `github-primer-homepage`, `base-ui-accordion-doc-page`, `mintlify-themes-2-0`, `performative-ui` — note `mintlify-themes-2-0` and `performative-ui` are themselves tagged `relation: trend-doc` in the raw data; counted here as peers, not commentary, since both are functioning design-system/component-kit products). All 5 recorded reviewer passes in `gate1.json` returned verdict `"gaps"` on exactly this skew (see §6). Read the ADOPT verdicts below as strong evidence for AI-startup/devtool marketing-site conventions, thinner (n=8) evidence for design-system-product-specific conventions, and treat the 10 trend-doc rows as claims needing their own live-crawled corroboration — never as site-count evidence on their own.

**Differentiators — the bets**

- **1.** **A live Theme Builder is the single highest-leverage build.** [prevalence evidence] Only 4-5/68 sites ship one, but every one maps directly onto Astryx's existing `defineVars`/`createTheme` primitives — `shadcn-ui-theming-docs`, `heroui-v3-formerly-nextui`, `radix-ui-themes-theme-overview-docs`, `park-ui-panda-css-ark-ui-homepage`, `mintlify-themes-2-0`. Well-funded peers (`mistral-ai`, `baseten`, `together-ai`) only document tokens as static prose — a live builder is still a differentiator, not table stakes, and it's the one pattern that turns Astryx's own architecture into the marketed product.
- **3.** **The hero should be the live product, not a screenshot.** [prevalence evidence] 12+/68 (`v0-app-formerly-v0-dev`, `rive`, `motion-motion-dev`, `park-ui-panda-css-ark-ui-homepage`, `heroui-v3-formerly-nextui`) run real, wired components as the hero visual. This is cheap for Astryx specifically because the components already exist — importing them is the whole cost.
- **6.** **Agent-readability has escalated from a file to a ladder, and it's the broadest single trend in the corpus — but it's three separate rungs, not one blended number.** [prevalence evidence] Per-rung dossier counts: **~26/68** ship a genuine, non-404 `llms.txt` (`cursor-cursor-com`, `mistral-ai`, `stripe-stripe-com`, `linear`, `lovable-dev`, `resend`, and others); **~7/68** reach the negotiation/mirror rung — HTTP `Accept`-header markdown negotiation or a per-page `.md` mirror (`elevenlabs`, `koah`, `resend`, `base-ui-accordion-doc-page`, `stripe-tour-of-the-api`); only **3/68** reach the top rung, a `.well-known` skill/agent manifest (`cartesia-ai`, `koah`, `pocket-heypocket-com`). Astryx should pick how far up this ladder to build rather than treat "18+" as one commitment — a bare `llms.txt` is table stakes, the negotiation rung is a real differentiator, the manifest rung is still rare. It also drifts stale in practice: `perplexity-ai`'s llms.txt 404s, `v0-app-formerly-v0-dev` ships none despite being AI-native, and `studiomeyer-io-web-design-trends-2026-reality-chec`'s own FAQPage JSON-LD omits subtopics present in prose. The fix is generation, not authorship discipline.
- **8.** **Bespoke display type as a third role, distinct from UI sans and code mono, is the strongest single typography pattern** [prevalence evidence] (20+/68: `lovable-dev`, `elevenlabs`, `mistral-ai`, `resend`, `cartesia-ai`, `modal-labs`) — but a real counter-camp of headless-UI-first systems (`heroui-v3-formerly-nextui`, `radix-ui-themes-theme-overview-docs`, `park-ui-panda-css-ark-ui-homepage`) stays plain sans on principle. Astryx should add the _slot_, not mandate the face.
- **12.** **The white-space gap: nobody combines a live theme builder + a generated (not hand-authored) agent-docs ladder + genuinely CSS-only restrained motion in one system.** [absence evidence] Theme-builder sites (`shadcn-ui-theming-docs`, `heroui-v3-formerly-nextui`, `radix-ui-themes-theme-overview-docs`) ship static docs prose and no agent-negotiation tier; agent-docs leaders (`elevenlabs`, `stripe-tour-of-the-api`) ship no live theme tooling; motion-restraint leaders (`safe-superintelligence-ssi`, `cognition-devin`, `github-primer-homepage`) have no product to demo at all. See §5.

**Table stakes — match the norm, don't look broken**

- **2.** **Warm cream/off-white, not pure white or default dark, is the corrected 2026 baseline.** [prevalence evidence] ~15/68 confirmed a warm neutral base (`lovable-dev` #FCFBF8, `elevenlabs` #FDFCFC), and several are explicit _live-CSS corrections_ of prior dark-by-default assumptions (`elevenlabs`, `cursor-cursor-com`, `world-labs-marble`). Dark stays real but concentrated in devtool/infra (`linear` #08090A, `modal-labs` #181818, `terminal-shop-charm` true black) — pick both as first-class theme presets, not one default plus an afterthought toggle.
- **4.** **CSS-only motion is now the majority position among serious dev-tools, not a compromise.** ~20/68 verified zero JS-animation-lib via bundle scan, including `cursor-cursor-com`, `zed`, `linear`, `heroui-v3-formerly-nextui`, `baseten`, `xai-grok` (`mistral-ai` is a near-miss, not a member: its dossier records one Lottie-rendered hero brand-mark as "the one third-party motion dependency detected," all-CSS otherwise — count and exemplar lists exclude it). Astryx's StyleX-only motion stance already matches this majority — the counter-camp (`world-labs-marble`, `together-ai`, `ploy`, `wembi`, `wispr-flow` on full GSAP) is agency-built consumer sites, not Astryx's peer set.
- **5.** **One reserved accent color, identical everywhere, beats a palette.** [prevalence evidence] ~15/68 (`openai-com-openai-sans-rebrand`, `cursor-cursor-com`, `xai-grok`, `modal-labs`, `cartesia-ai`, `linear`) confine color to a single accent used identically for CTA/link/selection/one H1 keyword. The loud counter-camp (`gumroad-neobrutalist-redesign`, `ploy`, `charm-charm-land`) is real but a deliberate minority stance, not the default to build toward.
- **7.** **Docs shells have fully converged — this is now a checklist, not a differentiator.** [prevalence evidence] ~10/68 (`shadcn-ui-theming-docs`, `base-ui-accordion-doc-page`, `radix-ui-themes-theme-overview-docs`, `park-ui-panda-css-ark-ui-homepage`, `github-primer-homepage`) run the identical fixed-nav / centered-prose / sticky-TOC / props-table / "View as Markdown" shape — even `performative-ui`, a joke library, reproduces it exactly. Astryx should match the shell and differentiate on voice, freshness, and theme tooling instead.
- **9.** **Decorative/ambient gradients, sparkle CTAs, and fake token-streaming now read as AI-slop, not polish.** [attention-verified] `performative-ui`'s satirical component kit (1,181 HN points) catalogs exactly this vocabulary as a warning; Anthropic's own frontend `SKILL.md` (`anthropic-s-frontend-design-skill-md-via-medium`, 277k+ installs in its first four months per its own dossier) independently bans decorative gradients and "cookie-cutter 3-card grids." Survivors are _functional_ gradients reused across contexts (`lovable-dev`'s hero-glow-doubles-as-text-sweep), not ambient blobs.
- **10.** **Reduced-motion is genuinely wired everywhere motion exists non-trivially — zero exceptions found.** [prevalence evidence] Every dossier with real motion also gates it for real: `adobe-spectrum-2-homepage` (user-facing autoplay switch), `stripe-stripe-com` (static PNG fallback), `onlook`, `linear` (static marquee fallback). This is converged practice for Astryx to mandate, not a nice-to-have.
- **11.** **Numbered-sequence IA (`01/02/03`) and bento grids are both past peak, contested by the closest peer set.** [prevalence evidence] 7/68 use numbered scaffolds (`vercel-geist-introduction`, `motion-motion-dev`, `cognition-devin`) but `studiomeyer-io-web-design-trends-2026-reality-chec` flags most use as unearned; bento appears on 6/68 (`stripe-stripe-com`, `bolt-new`) but Cursor/Zed/Linear/Cognition/SSI and Anthropic's own `SKILL.md` explicitly reject it. Neither should be Astryx's default template.

## 5. White-space map

Combinations no dossier in this corpus occupies — each is a specific, evidenced gap, not a hunch:

1. **Live Theme Builder + generated agent-docs ladder + genuinely CSS-only motion, all from one source of truth.** The theme-builder cluster (`shadcn-ui-theming-docs`, `heroui-v3-formerly-nextui`, `radix-ui-themes-theme-overview-docs`, `park-ui-panda-css-ark-ui-homepage`) ships static docs prose and no `llms.txt`/negotiation tier. The agent-docs leaders (`elevenlabs`'s content-negotiated Markdown, `stripe-tour-of-the-api`'s skill manifest) ship no live theme tooling at all. The motion-restraint leaders (`safe-superintelligence-ssi`, `cognition-devin`, `github-primer-homepage`) have no product to demo. Nobody has all three generated from the same `defineVars`/`tokens.stylex.ts` source — Astryx's architecture is the one place all three are already adjacent. **§4 rows:** spans the "Live Theme Builder" row and the "Generated `llms.txt` + `.md` mirrors + `DESIGN.md`" row; the CSS-only-motion leg is Astryx's existing StyleX baseline, not a separate take-list line.
2. **Component-gallery-as-hero for a design system itself, not a chat app or an infra vendor.** "Live product as hero" concentrates in either consumer chat apps (`v0-app-formerly-v0-dev`, `lovable-dev`, prompt-box-as-hero) or infra vendors demoing an API (`rive`, `motion-motion-dev`). Headless-UI-first systems (`heroui-v3-formerly-nextui`, `radix-ui-themes-theme-overview-docs`, `park-ui-panda-css-ark-ui-homepage`) stay on static prose/screenshots for their own homepage even though they build live-demo _infrastructure_ for their docs. `shadcn`'s `/create` is the closest single-site precedent, not a converged pattern. **§4 rows:** the "Hero = real rendered multi-component composition" row and the "'Built with Astryx' live-embed gallery" row.
3. **Per-component dated changelogs, not just a site-wide release timeline.** The dated-timeline pattern (`elevenlabs`, `cursor-cursor-com`, `zed`, `linear`, `github-primer-homepage`) is always a single site-wide page. No dossier shows a _per-component_ dated history inside its doc page — a natural extension for Astryx's `.doc.mjs` structure where each component's changelog lives beside its props table. **§4 row:** "Per-component dated changelog inside each `{Name}.doc.mjs`" (added alongside the site-wide Timeline row it extends).
4. **Build-generated (not hand-authored) agent-docs pipeline with a staleness CI gate.** Every agent-docs artifact in this corpus was hand-authored, and the corpus itself caught multiple going stale mid-crawl (`perplexity-ai`'s 404 llms.txt, `studiomeyer-io-web-design-trends-2026-reality-chec`'s own JSON-LD/prose mismatch, Anthropic's `SKILL.md` rewrite dropping its banlist, `mintlify-themes-2-0`'s theme-catalog rot, `onlook`'s 3×-stale star count, `webflow-blog-8-web-design-trends-to-watch-in-2026`'s dead example). Nobody ports the same recipe into documentation itself (e.g., a bundle-size-by-component-count tool) — a direct, evidenced extension rather than a new invention. **§4 row:** "Bundle-size-by-component-count live calculator."
